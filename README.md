# 1024 造物挑战 · 作品监控台

非官方的 **WorkBuddy「1024 造物挑战」程序员节应用创作大赛** 数据监控与 AI 分析应用。

实时同步官方活动页公开的作品墙与投稿池数据，用大模型按官方评审细则为每件作品生成模拟评分、技术栈推断与痛点分析，帮助参赛者了解竞争格局，帮助围观者快速发现好应用。

## 功能

- **实时监控**：作品墙上架数、投稿池审核结构（待审核/已通过/已驳回）、每日投稿趋势、最新投稿流水，60 秒同步
- **AI 评审团**：按官方细则（创意 35 + 完成度 40 + 体验 25，社媒潜力 30 参考）逐件生成模拟评分、一句话总结、痛点与解法、亮点、推断技术栈，全部附评分依据
- **作品库**：全量作品搜索/筛选/排序（卡片号、AI 评分、社区人气），点击任意作品查看完整 AI 画像
- **数据洞察**：每日投稿量、上架趋势、AI 评分分布直方图、审核结构、平台分布、热门标签、社区人气榜
- **社区互动**：访客可为作品投票、收藏（本地随机访客 ID 去重，不采集个人信息），一键生成分享战报图片
- **降级兜底**：上游异常时保留最后快照展示；AI 模块故障不影响数据看板

## 技术栈

- **后端**：Node.js 原生 HTTP 服务（零第三方依赖），定时轮询 + 快照落盘 + 静态托管，读取 `PORT` 环境变量
- **前端**：原生 HTML / CSS / JS 多页面 SPA（hash 路由），手写 SVG 图表，无构建步骤
- **云服务**（WorkBuddy Cloud）：免密钥大模型调用（Step-5-Preview）生成作品分析；云数据库（PostgreSQL + RLS）持久化分析结果与互动数据
- **设计系统**：赛事识别方向（Otl Aicher 慕尼黑奥运识别系统血统）——冷白纸底 + 单一信号橙红 + 黑色状态带 + 象图导航；`design-demos/` 目录保留了三个设计方向的完整初稿与设计决策记录

## 隐私与边界

- 仅采集活动**公开**的作品与投稿信息；官方存放联系电话的隐私表**不在采集范围内**（代码层面已隔离，见 `server.js` 头部注释）
- 互动功能仅在浏览器本地生成随机访客 ID 用于投票/收藏去重，不采集任何个人身份信息
- AI 评分为**模拟评审**，与官方评审结果无关，不构成获奖预测

## 本地运行

```bash
node server.js
# 默认 http://localhost:3000 ，可通过 PORT 环境变量修改
```

## 目录

```
server.js            零依赖 Node 服务：轮询、快照、静态托管
public/
  index.html         应用外壳（象图导航轨 + 状态带 + 页面容器）
  styles.css         设计系统（赛事识别方向）
  app.js             六页应用逻辑 + 图表 + 互动 + 分享战报
  cloud.js           WorkBuddy 云服务封装（LLM + 数据库）
  analysis.js        AI 分析管线（缓存 → 队列 → 落库）
design-demos/        三方向设计初稿、设计决策记录（directions.md）
```

## 风险提示

本应用依赖对官方活动页数据接口的解析。**若官方调整页面结构或接口，部分功能可能暂时失效**；此时将以最后一次成功快照继续展示，并尽快修复。
